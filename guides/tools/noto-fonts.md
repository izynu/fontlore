# Noto Fonts: workflow guide

What this reference covers: Noto Fonts as a Fontlore workflow tool: what it is, where it sits in the selection stage, how to use it well, and what evidence to record from it.

## What it is

Google's project to cover every script; the default answer for global products.

- Section: scripts
- Access: free
- URL: https://notofonts.github.io/

## Where it sits in the Fontlore workflow

This tool belongs to the **selection** stage. Concretely: confirm script coverage with real strings, not catalog checkboxes. It feeds records into the decision log, not opinions into the chat.

## How to use it well

- Go in with the project constraints written down: scripts, sizes, license scope, medium.
- Record what the tool returned, not what you hoped it would return.
- Prefer the tool's own primary data (files, license text, metadata) over summaries elsewhere.
- Combine with at least one independent source before treating a fact as verified.

## Evidence to record

When this tool contributes to a decision, log: the test strings used and per-script results.

## Limitations and cautions

Coverage tables lie by omission. Test diacritics, conjuncts, and mixed-script strings from the actual project.

## Common mistakes

- Copying tool output into the decision log without the URL and date.
- Letting one tool be the single source of truth for license facts.
- Using the tool outside its stage: identification tools do not verify licenses, catalogs do not test rendering.
