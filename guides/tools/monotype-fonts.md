# Monotype Fonts: workflow guide

What this reference covers: Monotype Fonts as a Fontlore workflow tool: what it is, where it sits in the implementation stage, how to use it well, and what evidence to record from it.

## What it is

Enterprise subscription platform for the Monotype library.

- Section: commercial
- Access: paid
- URL: https://www.monotypefonts.com/

## Where it sits in the Fontlore workflow

This tool belongs to the **implementation** stage. Concretely: compare license models and total cost before purchasing; perpetual vs subscription changes budgets. It feeds records into the decision log, not opinions into the chat.

## How to use it well

- Go in with the project constraints written down: scripts, sizes, license scope, medium.
- Record what the tool returned, not what you hoped it would return.
- Prefer the tool's own primary data (files, license text, metadata) over summaries elsewhere.
- Combine with at least one independent source before treating a fact as verified.
- Screenshot or archive the license terms at review time; terms change without notice.

## Evidence to record

When this tool contributes to a decision, log: the quote, license model, and renewal or perpetual status.

## Limitations and cautions

Pricing models change. Confirm terms at purchase time and keep receipts with the license register.

| Tool | Section | Access |

Siblings serve the same stage; pick one primary and keep one fallback in case the primary changes terms or disappears.

## Common mistakes

- Copying tool output into the decision log without the URL and date.
- Letting one tool be the single source of truth for license facts.
- Using the tool outside its stage: identification tools do not verify licenses, catalogs do not test rendering.
