# Fontspring Matcherator: workflow guide

What this reference covers: Fontspring Matcherator as a Fontlore workflow tool: what it is, where it sits in the identification stage, how to use it well, and what evidence to record from it.

## What it is

Glyph-based identification with commercial-free emphasis.

- Section: identification
- Access: free
- URL: https://www.fontspring.com/matcherator

## Where it sits in the Fontlore workflow

This tool belongs to the **identification** stage. Concretely: run the tool, then verify the candidate before treating the name as fact. It feeds records into the decision log, not opinions into the chat.

## How to use it well

- Go in with the project constraints written down: scripts, sizes, license scope, medium.
- Record what the tool returned, not what you hoped it would return.
- Prefer the tool's own primary data (files, license text, metadata) over summaries elsewhere.
- Combine with at least one independent source before treating a fact as verified.
- Treat outputs as candidate lists. Verification is a separate, mandatory step.

## Evidence to record

When this tool contributes to a decision, log: candidate list, verification result, and confidence level.

## Limitations and cautions

Automated identification returns candidates, not facts. Modified letterforms and custom lettering defeat these tools.

## Common mistakes

- Copying tool output into the decision log without the URL and date.
- Letting one tool be the single source of truth for license facts.
- Using the tool outside its stage: identification tools do not verify licenses, catalogs do not test rendering.
