# Google Fonts GitHub repository: workflow guide

What this reference covers: Google Fonts GitHub repository as a Fontlore workflow tool: what it is, where it sits in the research stage, how to use it well, and what evidence to record from it.

## What it is

Upstream font files, METADATA.pb, LICENSE files, and the axis registry.

- Section: source-repos
- Access: free
- URL: https://github.com/google/fonts

## Where it sits in the Fontlore workflow

This tool belongs to the **research** stage. Concretely: confirm the upstream source, license file, and latest release before relying on a family. It feeds records into the decision log, not opinions into the chat.

## How to use it well

- Go in with the project constraints written down: scripts, sizes, license scope, medium.
- Record what the tool returned, not what you hoped it would return.
- Prefer the tool's own primary data (files, license text, metadata) over summaries elsewhere.
- Combine with at least one independent source before treating a fact as verified.
- Pin versions: note the release, endpoint snapshot, or file hash alongside the retrieval date.

## Evidence to record

When this tool contributes to a decision, log: repository URL, license file path, and release or commit pinned.

## Limitations and cautions

Repository state changes. Pin the commit or release you verified and note the date.

## Alternatives and complements

No direct siblings in this section; cross-reference the broader source list in the references tree.

## Common mistakes

- Copying tool output into the decision log without the URL and date.
- Letting one tool be the single source of truth for license facts.
- Using the tool outside its stage: identification tools do not verify licenses, catalogs do not test rendering.
