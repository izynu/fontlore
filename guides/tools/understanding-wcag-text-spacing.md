# Understanding WCAG text spacing: workflow guide

What this reference covers: Understanding WCAG text spacing as a Fontlore workflow tool: what it is, where it sits in the selection stage, how to use it well, and what evidence to record from it.

## What it is

The exact spacing overrides your layout must survive.

- Section: accessibility
- Access: free
- URL: https://www.w3.org/WAI/WCAG22/Understanding/text-spacing

## Where it sits in the Fontlore workflow

This tool belongs to the **selection** stage. Concretely: check the typography decisions against WCAG requirements and real zoom behavior. It feeds records into the decision log, not opinions into the chat.

## How to use it well

- Go in with the project constraints written down: scripts, sizes, license scope, medium.
- Record what the tool returned, not what you hoped it would return.
- Prefer the tool's own primary data (files, license text, metadata) over summaries elsewhere.
- Combine with at least one independent source before treating a fact as verified.

## Evidence to record

When this tool contributes to a decision, log: the checks run (zoom, spacing overrides, contrast) and results.

## Limitations and cautions

Font choice alone cannot make a layout accessible. Size, spacing, contrast, and structure carry most of the weight.

## Common mistakes

- Copying tool output into the decision log without the URL and date.
- Letting one tool be the single source of truth for license facts.
- Using the tool outside its stage: identification tools do not verify licenses, catalogs do not test rendering.
