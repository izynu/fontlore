# FontForge: workflow guide

What this reference covers: FontForge as a Fontlore workflow tool: what it is, where it sits in the implementation stage, how to use it well, and what evidence to record from it.

## What it is

Open-source font editor for inspection and modification.

- Section: creation
- Access: free
- URL: https://fontforge.org/

## Where it sits in the Fontlore workflow

This tool belongs to the **implementation** stage. Concretely: investigate whether an existing family can be customized before commissioning work. It feeds records into the decision log, not opinions into the chat.

## How to use it well

- Go in with the project constraints written down: scripts, sizes, license scope, medium.
- Record what the tool returned, not what you hoped it would return.
- Prefer the tool's own primary data (files, license text, metadata) over summaries elsewhere.
- Combine with at least one independent source before treating a fact as verified.

## Evidence to record

When this tool contributes to a decision, log: the customization decision and its license implications.

## Limitations and cautions

Modifying a font changes your license obligations. Check the original license before editing and redistributing.

## Alternatives and complements

| Tool | Section | Access |
| --- | --- | --- |
| Glyphr Studio | creation | free |
| Glyphs | creation | paid |
Siblings serve the same stage; pick one primary and keep one fallback in case the primary changes terms or disappears.

## Common mistakes

- Copying tool output into the decision log without the URL and date.
- Letting one tool be the single source of truth for license facts.
- Using the tool outside its stage: identification tools do not verify licenses, catalogs do not test rendering.
