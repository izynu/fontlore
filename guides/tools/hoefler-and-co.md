# Hoefler and Co.: workflow guide

What this reference covers: Hoefler and Co. as a Fontlore workflow tool: what it is, where it sits in the research stage, how to use it well, and what evidence to record from it.

## What it is

Historic American foundry; licensing now via Monotype.

- Section: foundries
- Access: paid
- URL: https://www.typography.com/

## Where it sits in the Fontlore workflow

This tool belongs to the **research** stage. Concretely: read the foundry's own license and specimen pages; foundry data outranks aggregator data. It feeds records into the decision log, not opinions into the chat.

## How to use it well

- Go in with the project constraints written down: scripts, sizes, license scope, medium.
- Record what the tool returned, not what you hoped it would return.
- Prefer the tool's own primary data (files, license text, metadata) over summaries elsewhere.
- Combine with at least one independent source before treating a fact as verified.

## Evidence to record

When this tool contributes to a decision, log: family page URL, license name, and purchase or download path.

## Limitations and cautions

Foundry sites describe their own licenses, which vary per family. The family page, not the homepage, is the source of truth.

## Common mistakes

- Copying tool output into the decision log without the URL and date.
- Letting one tool be the single source of truth for license facts.
- Using the tool outside its stage: identification tools do not verify licenses, catalogs do not test rendering.
